Using Firn

Everything Firn does, one topic at a time. Generated from the app's own documentation.

Getting started

  1. Download Firn from the download section and open it. On a Mac the first start needs one extra step, described there.
  2. Choose a notes folder. Firn keeps your notes as Markdown files in a folder you pick, or creates a new Notes folder. Changes made in other editors show up right away.
  3. Add your calendars and contacts in Settings → Accounts. Several can be active at once:
  • On this computer: no syncing. Standard .ics/.vcf files inside your notes folder.
  • Nextcloud: sign in through the browser (Login Flow v2).
  • iCloud: Apple ID plus an app-specific password.
  • Google: OAuth with your own Google Cloud client; see Connecting Google.
  • Any CalDAV/CardDAV server: address, user name and password (discovered via /.well-known).

Passwords and sign-ins live in your system keychain. Server accounts sync every five minutes and whenever you ask, and the last copy stays available offline.

Getting around

  • The rail on the left holds the clock, the five screens (Today, Calendar, Todos, Notes, People, on ⌘1 … ⌘5), the Presenting switch, the sync status and Settings (⌘,).
  • Badges on the rail count lesson notes still waiting (Today) and open todos (Todos).
  • The theme follows the system unless set in Settings → Appearance (Match system / Light / Evening).

Omnibar: find anything, do anything

Open it with ⌘K (Ctrl+K), or / when you're not typing. ⌥Space (Alt+Space on Linux) opens it above any other app. ↑/↓ move, ↵ runs the highlighted row, Esc closes. A badge next to the input shows how your text was read (New todo, New note, Question, Proposed).

Commands. With nothing typed you get the list: go to a screen, start/stop presenting, open the daily note, and "New note from template: …" for every note in Templates/. When a lesson has just ended, "Add lesson note for …" sits on top.

Search. Type words; a row matches when every word is in it. Searches events (two weeks back to three weeks ahead), notes, todos and people.

7b              → the 7b lessons and the 7b notebook
anna            → Anna in People
quiz            → todos and notes about quizzes

Create without AI. Start with todo (or task), event (or termin) or note. Greyed-out hints in the input show the syntax you haven't used yet.

Token Meaning
#tag project tag
!high (or !, !!, !h) high priority
@List list (name or its beginning)
today, tomorrow, fri, 12.10., 2026-10-12 (also heute, morgen, fr) due date 
todo Mark quizzes #9a !high fri @School
task Call plumber tomorrow
note Ideas for parents evening          → Inbox/Ideas for parents evening
note Projects/Garden plan               → that exact path

Events use the calendar's quick-add words: a date (fri, 12.10.), a time (16:30), a duration (30min, 1h, default one hour) and @Calendar. Without a date or time an event starts today at 09:00.

event Parent call fri 16:30 30min @School
termin Zahnarzt 12.10. 15:00

A todo from the omnibar is due today unless you give a date. Any other text also offers "New note …" and "Add todo …" at the bottom.

Ask about your schedule. Questions are answered from your calendar and todos, no language model needed. A question ends in ? or starts with what, when, which, do I, have I, anything, was, wann, welche, habe ich, steht.

what do I have tomorrow?
anything on friday?
was steht am 14.10. an?

You get that day's events and due todos plus "Open … in Calendar"; ↵ opens the first one.

Find the next or last one. Ask with next or last (also nächste, letzte) and the omnibar searches your calendars about a year ahead or back, in titles, places, notes and the people on an event.

when is my next therapy session?   → the next "Therapie" events, with "in 9 days"
next meeting with Anna             → meetings Anna is on
when was my last haircut?
wann ist das nächste Elterngespräch?

Words no event contains ("session") are skipped; every other word has to match. Questions about a date ("what's on next week?") still go to the agenda.

Ask about a person. Name someone and what you want to know; the answer comes from their note in People/.

What could I gift Annika?        → the "Gift ideas" section of Annika's note
Geschenkideen für Jonas          → same, in German
is Anna allergic to anything?    → the lines in Anna's note that mention allergies
anna ceramics                    → matching lines first, then the usual search results

A section whose heading matches the question answers it (gift questions find any heading with gift, present or Geschenk). Without one, the lines that mention the topic answer it, so unstructured notes work too. Gift questions always answer, with "Nothing on gift ideas yet" if there are none.

Sentences (optional local model). With Settings → Language models → Local model set to Ollama, a sentence of three or more words offers "Turn into an action". ↵ reads it on this computer and proposes one todo, event or note; ↵ again does it.

lunch with Sarah next tuesday at 12:30 for 90 min   → event, Tue 12:30–14:00
remind me to renew passport by Monday, urgent        → high-priority todo due Monday
Zahnarzt am 12.10. um 15 Uhr                         → event
idea: let students vote on the reading list          → new note

The model only sorts the sentence and picks out the words; the app works out dates, times (12:30, 3pm, 15 Uhr), durations (for 2 hours, 90 Minuten) and priority (important, urgent, asap, wichtig, dringend). Install Ollama and run ollama pull qwen2.5:3b (the recommended model: on a 16 GB M1 it read every test sentence correctly in about a second).

New note from a template. Pick "New note from template: …", type the title, ↵. {{title}} and {{date}} are filled in; Meeting notes go to Projects/, others to Inbox/.

Today

  • The headline says what's next ("Next: Maths · 7b at 09:55, Room 204") or what's running, and flips like a station board when that changes.
  • The board lists today's timed events with their status: Now, Next, Later, Done, Cancelled, and for lessons Add note / Note later / No note / Noted. Click a row to see its notebook (with the last entry), people and calendar.
  • Lesson notes. When a lesson ends, a capture line asks "What did 9a do in Maths today?". Type, ↵ (Shift+↵ for a new line). It's appended to the class notebook under ## YYYY-MM-DD · <title>. Later (Esc) keeps it waiting; No note for this lesson dismisses it.
  • The side column shows Due today (tick to complete), Birthdays in the next 14 days and today's Daily note ("Open daily note" / "Start today's note").

Calendar

  • Week and Month tabs, ‹ Today ›. Keys: t today, w week, m month, Alt+←/→ previous/next, Esc closes the editor.
  • Quick add (top line): Parent call fri 16:30 30min @School. Time 16:30/16.30/16h30, duration 30min/1h (default 60 min), date words as for todos, @Calendar. A date without a time starts at 09:00.
  • Mouse. Drag on empty space to create, drag an event to move it (also to another day), drag its bottom edge to resize. Snaps to 15 minutes. In Month, click a day to open its week.
  • Editor. Title, Calendar, Date, From, To, All day, Repeat (day/week/month), Class or Group, Place, People (type a name or a group), Notes. ⌘↵ saves. For a repeating event, Save and Delete ask: only this one, this and all following, or the whole series. Dragging a repeating event changes only that occurrence.
  • Calendars ▾ shows or hides each calendar and changes its colour (eight hues; written back to the server when it allows).
  • The Due strip above the grid shows todos per day; birthdays appear as all-day bars.
  • Subscribed calendars are read-only.

Todos

  • Views: Today (overdue and due today), Upcoming, Lists (one list or all side by side), Projects (one #tag), From notes, No date, Done. Choose and reorder them in Settings → Todos.

  • Quick add (⌘N): Mark quizzes #9a !high fri @School. New todos go into the list or project you're looking at; from the Today view they're due today.

  • Click a title to expand: steps (sub-tasks), notes, due date, list, linked note, tags, priority, delete. Completing a todo with open steps asks whether to complete them all.

  • Todos in notes. Any checkbox in a note shows up under From notes:

    - [ ] Mark the 9a quizzes 📅 2026-10-09 #school ⏫
- [x] Order goggles ✅ 2026-10-06

    📅 date makes it due, ⏫ or 🔺 high priority. Ticking it in the app rewrites the line and adds ✅ date. These stay in your notes and are never sent to a server. Checkboxes under a Gift ideas heading are ideas, not todos, and are left out.

Notes

  • Notes are plain Markdown files in a folder you choose on first run (Settings → Notes folder → Choose…). The app creates Daily/, People/, Projects/, Templates/ (and Classes/ when teaching); Inbox/ and Books/ appear when needed. Changes from other editors show up live.
  • New note: ⌘N (opens the omnibar with note ). New notebook: the folder-plus icon; Projects/2026 nests it.
  • … menu: Rename (updates every link to it), Move to…, Delete (goes to .home/trash/, recoverable).
  • Editor. ⌘E switches Live and Source. Live renders Markdown in place and hides frontmatter behind a Properties block; edit frontmatter in Source. Checkboxes are clickable.
  • Links. Type [[ to link another note (autocompletes). Also [[Note|alias]] and [[Note#heading]]. Click to follow (⌘-click on the line you're editing); a link to a note that doesn't exist yet creates it. Each note lists its backlinks at the bottom.
  • Daily note: Daily/YYYY-MM-DD, made from Templates/Daily note; {{events}} becomes the day's events with links to their notebooks.
  • Context panel (⌘J): local graph, outline, related lessons/events, people, file info. Graph (⌘G): every note and link, with a highlight search and an option to show missing notes. ⌘\ hides the folder pane.
  • Frontmatter the app understands: type, group, tags, contact, birthday, author, private: true (hidden while presenting), capture: (see Teaching).
  • Import (Settings → Notes folder): Joplin (export as "MD - Markdown + Front Matter", lands in Joplin/) and Reed (a reed-notes .json file, one note per book in Books/). Imports never overwrite.

People

  • Contacts from your address books plus people who exist only as notes in People/. Search "Find a person", or filter by Everyone / contacts / only in my notes / a group.
  • New person: name, then "Only in my notes" or as a contact. Edit: role, phone, email, address, birthday (10.10. or 10.10.1958), groups.
  • Each person has a note ("Start a note"). New person notes start with the sections Gift ideas, To remember and Log, taken from Templates/Person (edit it to change them; without it the app uses these three). Structure is optional: the omnibar reads free text too. Each person also has a Mentioned in list of events, todos and notes that link to them. Birthdays show on Today, in the calendar and in the briefing.

Teaching and lesson notes

  • Turn on I teach (first run or Settings). It switches wording to lessons and classes and adds Classes/ and a Lesson template.

  • A class notebook asks for a note after each matching lesson. Its frontmatter:

    type: notebook
group: 9a
capture:
  when: event-ends
  calendar: Stundenplan   # optional
  title: Mathematik 9a*   # * matches anything; without it, "contains"

  • In People, filter by a group and choose Make 9a a class to create such a notebook. Settings → Teaching lists every trigger.

Presenting

Turn it on with the rail switch, ⌘⇧P or the omnibar; it also starts by itself when a second display connects (Settings → Presenting). While presenting the app hides todos, people, contact notes and private: true notes, shows private events as "Busy", holds lesson notes and notifications, and locks private events. Mark calendars private in Settings → Calendars & lists.

Morning briefing and notifications

At the time set in Settings → Morning briefing (default 07:15, optionally school days only) the app brings Today forward and sends a "Good morning" notification: today's events, todos due, birthdays. "Notify when a lesson ends" sends a notification after each lesson. Both need the app running: turn on Open at login. If the app wasn't running at that time, Catch up when the app starts later shows the briefing at start.

Accounts and sync

Accounts are set up as in Getting started. Day to day:

  • Server accounts sync every five minutes, when you come back to the window, and with Sync. Offline, the last copy is shown and changes sync later.
  • The first three saves to a server ask first ("Don't ask again"). If something changed elsewhere since the app last saw it, you choose Keep Nextcloud's (the server's version) or Use mine.
  • Notes sync (Settings → Notes sync, Nextcloud): pick a server folder and Turn on sync. Conflicts become Name (conflict …).md copies, listed in Settings. A sync that would delete many notes waits for you. Off automatically for folders already synced by iCloud Drive, Dropbox, Syncthing or the Nextcloud desktop app.
  • Reed book notes: with notes sync on, Settings → Notes sync → Book notes from Reed → Pick up. Notes from Reed appear in Books/; edits go both ways.

Known gaps

  • Todos written in notes can't be promoted to a server list yet.
  • Only "event ends" triggers fire; there is no trigger editor besides Make class.
  • No cloud model yet; notebooks (folders) can't be renamed or deleted; contacts can't be deleted.

Connecting Google

Google only lets an app read and write calendars and contacts after the app is registered with Google. Because this app is just for you, you register it once in your own (free) Google Cloud project. It takes about 10 minutes.

1. Create a project

  1. Open https://console.cloud.google.com/ and sign in with the Google account whose calendars you want.
  2. Top bar → project picker → New project. Name it e.g. Firn. Create it and select it.

2. Turn on the two APIs

  1. Menu → APIs & Services → Library.
  2. Search CalDAV API → Enable.
  3. Search Google Contacts CardDAV API → Enable.

3. Consent screen

  1. APIs & Services → OAuth consent screen (or Google Auth Platform → Branding).
  2. User type External → Create. App name Firn, your email as support and developer contact. Save.
  3. Audience / Test users → Add users → add your own Google address. (While the app is in Testing, only listed users can sign in. That's what you want.)
  4. Data access / Scopes: you can leave this empty; the app asks for the calendar and contacts scopes when you sign in.

4. Create the client

  1. APIs & Services → Credentials → Create credentials → OAuth client ID.
  2. Application type Desktop app. Name Firn desktop. Create.
  3. Copy the Client ID and Client secret. (For desktop apps Google doesn't treat the secret as confidential; it identifies the app, it doesn't unlock your data.)

5. Sign in from the app

Settings → Accounts → Add an account → Google → paste the client ID and secret → Sign in with Google. Your browser opens Google's consent page; after you allow access the app stores a refresh token in your system keychain.

If something goes wrong

  • "Access blocked: app has not completed verification": your address isn't in Test users (step 3.3).
  • "redirect_uri_mismatch": the client isn't a Desktop app (step 4.2). Desktop clients accept the app's http://127.0.0.1:<port> redirect automatically.
  • In Testing mode Google expires refresh tokens after 7 days. To stop that, publish the app (consent screen → Publish app); for personal use Google doesn't require verification, you'll just see an "unverified app" warning once.
